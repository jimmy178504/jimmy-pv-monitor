# Jimmy PV Monitor トラブル対応・復旧マニュアル

このマニュアルは、Jimmy PV Monitorの導入・更新・利用中に問題が起きたとき、サイトへの影響を抑えて安全に復旧するための手順です。

配布用ZIPはGitHub上では公開していません。再インストールや更新に使うZIPは、[Jimmy PV Monitor ダウンロードページ](https://jimmy-blog.com/jimmy-pv-monitor/)から入手してください。

WordPressやサーバーに詳しくない場合は、無理に作業を続けず、利用中のレンタルサーバー会社やサイトの保守担当者へ相談してください。

## 最初に確認すること

問題が起きたら、次の順番で行動してください。

1. プラグインや解析データをすぐに削除しない
2. エラーが出た時刻、操作、画面、エラー文を記録する
3. 可能なら現在のファイルとデータベースをバックアップする
4. 問題が起きる前の復元可能なバックアップがあるか確認する
5. 影響が大きい場合はJimmy PV Monitorの計測またはプラグインを一時停止する
6. サイトの公開画面と管理画面が表示できるか確認する

原因を調べる前に複数の設定やファイルを同時に変更すると、原因や元に戻す方法が分からなくなります。変更は一つずつ行い、変更内容と時刻を記録してください。

## バックアップするもの

サイトを完全に戻すには、原則として次の両方が必要です。

- WordPressのファイル
- WordPressのデータベース

ファイルには、少なくとも`wp-content`、利用中のテーマとプラグイン、画像などのアップロードファイル、WordPressの設定ファイルが含まれることを確認してください。

データベースには、記事、設定、Jimmy PV Monitorの解析データなどが保存されています。ファイルだけ、またはデータベースだけのバックアップでは、完全に復元できないことがあります。

次の点も確認してください。

- ファイルとデータベースを近い時刻に取得している
- バックアップをサーバーとは別の場所にも保管している
- 複数世代のバックアップを残している
- 復元手順と必要なログイン情報が分かる
- 可能であればテスト環境で復元を試している

## 重大なエラーや白い画面が表示された

「このサイトで重大なエラーが発生しました」と表示された場合や、画面が真っ白になった場合の手順です。

### WordPressから復旧案内メールが届いている場合

1. WordPress管理者のメールを確認します。
2. WordPressから届いた「リカバリーモード」の案内を開きます。
3. 案内に従って管理画面へ入ります。
4. 問題のあるプラグインとしてJimmy PV Monitor Proが示されている場合は、先にPro版を停止します。
5. Free版が示されている場合、またはPro版の停止だけで直らない場合は、Free版も停止します。
6. 公開画面と通常の管理画面が表示できるか確認します。

### 管理画面に入れない場合

レンタルサーバーのファイル管理画面、またはFTPを使います。分からない場合はサーバー会社へ依頼してください。

1. `wp-content/plugins`フォルダーを開きます。
2. Pro版を利用している場合は、`jimmy-pv-monitor-pro`の名前を`jimmy-pv-monitor-pro.disabled`へ変更します。
3. サイトを再読み込みします。
4. 直らない場合は、`jimmy-pv-monitor`の名前を`jimmy-pv-monitor.disabled`へ変更します。
5. サイトの公開画面と管理画面を確認します。

この操作はプラグインを一時的に読み込ませないためのものです。フォルダーは削除しないでください。データベース内の解析データを消す操作でもありません。

復旧後に再び有効化するときは、先にバックアップを取得し、問題がなかったバージョンを用意してください。Free版を先に有効化して確認し、その後にPro版を有効化します。

## サイトが急に重くなった、503・504エラーが出る

503や504などのエラーは、サーバーやデータベースの処理能力不足、アクセス集中、ほかのプラグインなど、複数の原因で起きることがあります。

1. 管理画面へ入れる場合は、「Jimmy PV」→「設定」でPV計測を一時停止します。
2. 改善しない場合は、Pro版、Free版の順で一時停止します。
3. キャッシュ機能を利用している場合は、キャッシュを削除して再確認します。
4. サーバー会社へ、問題が起きた時刻のCPU、メモリー、データベース負荷、エラーログの確認を依頼します。
5. 直前に行ったプラグイン更新や設定変更があれば記録します。
6. 必要に応じて、問題が起きる前のバックアップへ戻します。

解析データを削除する前に、必ずデータベースをバックアップしてください。原因が分からない段階で「全データを削除」やアンインストール時のデータ削除を行わないでください。

Jimmy PV MonitorはDocker環境で1日最大1万PV相当の負荷試験を実施していますが、すべての利用環境で同じ性能を保証するものではありません。1日の合計PVが同じでも、短時間へのアクセス集中、サーバー性能、データ量、ほかのプラグインによって負荷は変わります。

## 公開画面は表示できるが、Jimmy PVの管理画面だけエラーになる

1. エラー文と発生時刻を記録します。
2. WordPress、PHP、Free版、Pro版のバージョンを記録します。
3. 直前にFree版またはPro版を更新していないか確認します。
4. バックアップを取得します。
5. Pro版を利用している場合はPro版を一時停止して確認します。
6. 改善しない場合はFree版を一時停止します。
7. 手元のバックアップ、またはジミログ内の配布案内から入手したZIPを使い、プラグインファイルを戻します。

プラグインファイルだけを戻す場合でも、先にファイルとデータベースをバックアップしてください。Free版とPro版には対応する組み合わせがあるため、片方だけを古い版へ戻すと問題が起きる場合があります。

## PVが増えない

PVが増えないだけで公開サイトが正常に表示されている場合は、緊急停止や復元を急ぐ必要はありません。次の順番で確認します。

1. 「PV計測を有効にする」がオンか確認する
2. 管理者としてログイン中の閲覧が除外されていないか確認する
3. 一般公開された記事で試す
4. シークレットウィンドウ、またはログアウトしたブラウザーで試す
5. 投稿タイプ、投稿ID、URLの除外設定を確認する
6. キャッシュ、セキュリティ対策、広告ブロックの影響を確認する
7. キャッシュを削除して数分後に再確認する

## クリック計測が増えない

1. クリックした日時が選択中の期間に含まれているか確認します。
2. 「記事内リンクの読み取り」が完了しているか確認します。
3. 必要に応じて「リンクを読み直す」を実行します。
4. 公開画面で実際にクリックして確認します。
5. キャッシュを削除して再確認します。

プラグイン導入前や、各リンク種別のクリック計測に対応する前のクリックを後から復元することはできません。

## 数字がおかしい、二重に計測される

1. 問題に気づいた日時と対象ページを記録します。
2. 必要なデータをCSVへ出力します。
3. ファイルとデータベースをバックアップします。
4. 影響が大きい場合はPV計測を一時停止します。
5. キャッシュ機能や、同じ目的のアクセス解析プラグインが重複して動作していないか確認します。
6. WordPressのタイムゾーンと、レポートで選択した期間を確認します。

原因の確認が終わる前に解析データを削除しないでください。誤った数字が残っていても、調査や修正に利用できる場合があります。

## データベース容量が増えすぎた

1. 現在のデータベースをバックアップします。
2. サーバー会社へデータベース容量を確認します。
3. Jimmy PVの「日別データ保存日数」を必要な範囲で短くします。
4. 計測不要な投稿タイプやURLを除外します。
5. 日次保守が正常に予約されているか確認します。

保存日数を短くすると、保存期間を過ぎた日別データは日次保守で削除されます。必要なデータは先にCSVへ出力し、データベースもバックアップしてください。

## バックアップから戻す判断

### プラグインファイルだけを戻す場合

更新直後にプラグインの画面だけで問題が起き、データベースに問題がないと判断できる場合です。問題がなかったFree版とPro版の組み合わせへ戻します。

### ファイルとデータベースを戻す場合

解析データや設定が壊れた可能性がある場合、データベース更新の途中で問題が起きた場合、またはサイト全体で不整合が起きている場合です。原則として、同じ時点で取得したファイルとデータベースを一組として戻します。

復元すると、バックアップ取得後に追加・更新された記事、コメント、注文、設定、解析データなどが失われることがあります。影響範囲を確認し、可能であれば本番サイトへ戻す前にテスト環境で復元してください。

## 復旧後の確認

1. 公開ページを複数表示し、正常に閲覧できるか確認します。
2. WordPress管理画面へ入れるか確認します。
3. Free版だけを有効化し、PV計測と各画面を確認します。
4. Pro版を利用する場合は、その後にPro版を有効化して確認します。
5. 数時間から1日程度、エラーとサーバー負荷を注意して確認します。
6. 新しい正常なバックアップを取得します。

## 相談するときに用意する情報

- 問題が起きた日時
- 直前に行った操作、更新、設定変更
- 表示されたエラー文の全文と画面の画像
- 問題が起きた管理画面の名前やURL
- WordPressのバージョン
- PHPとデータベースのバージョン
- Jimmy PV Monitor FreeとProのバージョン
- 利用中のテーマ名
- キャッシュ、セキュリティ、アクセス解析に関係するプラグイン名
- おおよその1日PVと、問題発生時のアクセス状況
- 利用中のレンタルサーバーと契約プラン
- 復元可能なバックアップの取得日時

パスワード、秘密鍵、APIキー、`wp-config.php`の内容、データベースの完全な中身は、GitHubなどの公開場所へ投稿しないでください。
